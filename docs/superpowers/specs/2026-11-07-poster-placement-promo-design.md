# 포스터 자리·걸기·홍보 길 설계 (2026-11-07)

> 앞선 설계: `docs/superpowers/specs/2026-11-05-ai-poster-design.md`(AI 포스터), `docs/superpowers/specs/2026-11-06-poster-mac-art-design.md`(학교 Mac 그림). 지금 동작은 `.claude/rules/posters.md`.

## 1. 왜

AI 포스터를 학생에게 열 때가 됐다(지금은 `POSTER_OPEN_TO_ALL = false`, 관리자만). 그 전에 두 가지가 비어 있다.

1. **자리**: 포스터 화면(`/projects/[id]/poster`)은 상세 페이지 "홍보 포스터" 버튼으로만 들어가고, 메뉴에선 "모든 프로젝트" 아래로 잡힌다. 사용자는 **"프로젝트 등록"과 묶이길** 원한다.
2. **쓰임**: 포스터는 학교 게시판에 출력해 붙이지만, **사이트 안에서도 포스터로 홍보**되길 원한다. 시작은 프로젝트 상세 페이지, 나중에 넓힌다.

홍보 길(학생이 기능을 알게 되는 길)은 사용자가 고른 장면: **남의 상세 페이지에 들어갔다가 처음 보는 포스터를 봤을 때.** 포스터가 포스터를 부르는 흐름이다. 처음 걸릴 포스터는 사용자가 몇몇 주인에게 직접 부탁한다(관리자가 남의 프로젝트에 대신 걸지 않음).

## 2. 목표 / 안 할 것 / 실패로 볼 것

**목표**
- 상세 페이지 오른쪽 옆칸 맨 위에 **걸린 포스터 하나**를 보여 준다. 누르면 크게.
- 프로젝트 주인·팀원이 포스터 여러 개 중 **하나를 골라 건다**. 후보 = AI 포스터 + **직접 만든 포스터 그림 올리기**.
- 등록·수정 폼에 **선택 항목 카드 "홍보 포스터"**.
- 이미 등록한 주인에게 상세 페이지에서 **주인에게만** 권유 카드(도메인 권유처럼).
- 크게 보기 창 아래 한 줄로 **"내 프로젝트로도 만들 수 있어요"** 연결.
- 같은 배포로 **AI 포스터를 학생에게 연다**(플래그 + 처리방침).

**안 할 것**
- 메뉴 칸 추가, 메뉴 안 **탭 분할**(커뮤니티 같은 "A | B" 세그먼트 — 사용자: "정말 최악").
- 공지·홈 띠·홈 섹션으로 따로 알리기(이번엔 안 함, 나중에 넓힐 때).
- 포스터 모아 보기 게시판(나중).
- 관리자가 남의 프로젝트에 포스터를 대신 걸기.
- 직접 올린 포스터에 띠 자동 합성.

**실패로 볼 것**
- **hover로 커지기** — 사이트 규칙(hover 확대·떠오름 금지)을 그대로 지킨다. 사용자가 명시적으로 유지 결정.
- 주인이 고르지 않은 포스터가 저절로 걸리는 것.
- 비공개 프로젝트 포스터가 남에게 보이는 것.
- 권유 카드가 여러 장 겹쳐 상세 머리가 지저분해지는 것.

## 3. 상세 페이지 표시 (사용자 결정: 시안 A)

- 자리: `project-detail-view.tsx` 오른쪽 옆칸(`개발자`/`팀` 박스 위) 맨 위. 모바일(1열)에선 옆칸 순서 그대로 — 상세 설명 아래, 개발자 위.
- 걸린 포스터가 없으면 아무것도 안 그린다(빈 자리·자리표시 없음).
- **공개 프로젝트일 때만** 보인다(`visibility === 'public'`). 비공개로 바뀌면 숨김(지우지 않음 — 다시 공개하면 다시 보임).
- 보이는 크기: 옆칸 폭에 맞춘 세로 그림, 비율은 그림 그대로(`object-contain`, A4가 아니어도 됨), `rounded-2xl` 정도 + 얇은 테두리.
- **누르고 싶게 하는 효과**(사용자: "살짝 효과를 주든지") — 크기·위치 변화 없이:
  - 오른쪽 아래 모서리에 작은 알약 "크게 보기"(돋보기 아이콘).
  - 마우스를 올리면 테두리 색만 진해짐(`transition-colors`), 커서 `zoom-in`.
  - 키보드: `<button>`으로 감싸 Tab·Enter 동작, `aria-label="포스터 크게 보기"`.
- **크게 보기**: 공용 `Dialog`. 화면 높이에 맞춘 큰 그림(`max-h-[calc(100dvh-…)]`), Esc·× 닫기, 모바일은 화면 꽉 차게. `alt`는 "<프로젝트 이름> 홍보 포스터".
- AI 포스터면 크게 보기 창에 작은 알약 **"AI로 만든 포스터"**. 직접 올린 건 안 붙임.
- 빠른 상세(목록에서 누를 때 브라우저가 Supabase로 바로 그리는 화면, `.claude/rules/projects.md`)에도 똑같이 보여야 한다 → 걸린 포스터 정보는 **anon 키로 읽을 수 있는 곳**에 둔다(§6).

## 4. 홍보 한 줄 (크게 보기 창 아래)

- 문구: "이 포스터, 내 프로젝트로도 만들 수 있어요 →" (해요체, 카피는 다듬어도 됨).
- 누르면:
  - 비로그인 → `/login?next=…`(로그인 뒤 아래 규칙대로).
  - 로그인 + 내가 고칠 수 있는 공개 프로젝트가 1개 → 그 프로젝트 포스터 화면.
  - 여러 개 → 내 프로젝트 고르기(작은 창 또는 간단한 목록 페이지 — 빌더 판단, 탭 분할만 아니면 됨).
  - 없음 → `/projects/new`.
- 자기 프로젝트 상세에서 크게 볼 땐 이 줄을 안 보인다(대신 포스터 화면으로 가는 "포스터 바꾸기" 링크 — 빌더 판단).

## 5. 들어가는 길

### 5-1. 등록·수정 폼 — 선택 카드 "홍보 포스터"
- `ProjectForm`의 `FormSection` 카드로 하나 추가(현재 5장 뒤, "위험 구역" 앞). **필수 아님** — `FormRail` 목차엔 보이되 "필수 항목 N / 6" 수에는 안 셈.
- 카드 안 두 가지:
  1. **포스터 그림 올리기** — 포스터 전용 올리기 경로(§9). 올리면 "상세 페이지에 걸어요" 체크(기본 켬).
  2. **등록한 뒤 AI로 만들기** — 체크하면 저장 성공 뒤 그 프로젝트 포스터 화면으로 이동.
- 공개 범위가 비공개면 카드에 "공개 프로젝트만 상세 페이지에 걸려요" 한 줄(막지는 않음 — 올린 건 저장, 걸기는 공개일 때만 보임).
- 수정 폼: 같은 카드 + 지금 걸린 포스터 미리보기 + "포스터 화면에서 고르기" 링크.
- 등록 직후 "도메인 마련하기" 권유 창과 겹칠 때: **AI로 만들기를 체크했으면 포스터 화면이 우선**, 도메인 권유는 나중에 상세 페이지 권유 카드로(§5-2) 다시 뜬다. (내 판단)
- 중복 등록 방지(폼 잠금·DB 10분 트리거)와 같이 동작해야 한다 — 포스터 저장은 프로젝트 저장이 성공한 뒤.

### 5-2. 이미 등록한 주인 — 상세 페이지 권유 카드
- `DomainNudge`와 같은 자리·모양(이어서 보기 카드: 안내 줄 + 제목 + 버튼 하나 + ×). 이름 예: `PosterNudge`.
- 조건: **주인만**(도메인 권유와 같은 판정 — `public_author_id` 또는 익명이면 `my_project_ids`, 개발자 계정·팀원 제외), 공개 프로젝트, **걸린 포스터 없음**.
- 버튼 → `/projects/<id>/poster`. ×는 `localStorage['poster-nudge-dismissed:<id>']`.
- **한 번에 한 장만**: 미리보기 주소 경고 > 옛 주소 바꾸기 > 도메인 권유 > 포스터 권유. 앞의 것이 뜨면 포스터 권유는 안 뜬다. (내 판단)

### 5-3. 메뉴
- 메뉴 칸은 그대로 5칸.
- `/projects/[id]/poster/*`에 있을 때 활성 칸을 **"프로젝트 등록"**으로(지금은 "모든 프로젝트"). `.claude/rules/nav.md` 활성 판정 표 갱신.
- 상세 페이지 기존 "홍보 포스터" 버튼은 유지.

## 6. 포스터 고르기·걸기

### 데이터 (빌더가 최종 결정, 아래는 요구 사항 + 내 제안)
- `project_posters`에 **종류** 구분: AI(`html` 있음) / 직접 올림(그림 URL만). 직접 올린 것도 같은 표에 넣고 "프로젝트당 개수"(`poster_limit`)를 같이 쓴다 — 합쳐서 5개(§9). **"새 포스터 하루 1개"(`poster_daily`)는 AI만** — AI 비용 때문에 만든 제한이라.
- 걸린 포스터 = **공개 표시용 그림 URL 하나**. 상세 페이지·빠른 상세가 anon 키로 읽어야 하고 `project_posters`는 RLS 정책 없음(서비스 키 전용)이라, 제안: `projects`에 칸(예: `poster_image_url`, `poster_id`, `poster_is_ai`)을 두고 projects RLS(공개/비공개)에 맡긴다.
  - **새 칸은 `GRANT SELECT (칸) ON public.projects TO anon, authenticated` + `PROJECT_COLUMNS` 추가 필수**(CLAUDE.md 익명 프로젝트 규칙).
  - 사용자 키로 직접 못 바꾸게 잠금(identity 잠금 트리거와 같은 방식) — 걸기·내리기는 서버 액션이 권한 확인 뒤 서비스 키로.
- **AI 포스터를 걸 때**: AI 포스터는 HTML(샌드박스 iframe)이라 그대로 걸지 않는다. 걸기 = 지금 내보내기와 같은 Browser Rendering으로 **PNG를 만들어 Cloudinary에 올리고 그 URL을 건다**(띠 포함 — 게시판에 붙는 모습 그대로). 걸린 뒤 포스터를 고치면 포스터 화면에 "걸린 뒤 고쳤어요 · 다시 걸기" 표시(자동으로 다시 찍지 않음 — Browser Rendering 429·요청 수 아끼기). (내 판단)
- 직접 올린 그림: PNG·JPEG·WebP만, 포스터 전용 올리기 경로(§9). 띠 합성 안 함.
- 걸린 포스터를 지우면 자동으로 내려간다.

### 화면 (포스터 목록 `/projects/[id]/poster`)
- 각 포스터 카드에 "상세 페이지에 걸기" / 걸린 카드엔 "걸려 있어요" 표시 + "내리기". 하나만 걸림(다른 걸 걸면 바뀜).
- 목록에 **"포스터 그림 올리기"** 추가(등록 폼과 같은 업로드). AI 만들기는 `POSTER_OPEN_TO_ALL` 이후 누구나(관리자 제한 해제).
- 걸기·내리기 권한: 포스터 화면에 들어올 수 있는 사람(지금 `canEdit` — 주인·팀원). 차단된 사람은 불가(기존 판정 그대로).

## 7. 학생에게 열기 (같은 배포)

- `POSTER_OPEN_TO_ALL = true`.
- 처리방침(`src/lib/privacy/policy.ts`) 한 번에 고침 → 전원 재동의 한 번:
  - Google Gemini 위탁(설계 2026-11-05 §9 — 학습 가능성 포함).
  - Cloudinary 항목에 **포스터 그림**(올린 것·AI 그림·걸린 PNG) 추가.
  - 탈퇴 시 포스터 그림도 Cloudinary에서 지우기(`withdrawAccount`의 이미지 목록에 추가).
- **올리면 바로 걸리고 관리자는 나중에 검토**(사용자 결정 2026-11-07 — 승인 대기 없음). 관리자 대시보드 `/admin` 「최신 글」에 **새로 걸린 포스터**를 보이고 관리자가 내릴 수 있게. 올린 사람 차단은 기존 기간 차단 기능으로.
- **탭 닫힘 문제(Cloudflare Queues 이전)는 이번에 안 고치고 연다**(사용자 결정 2026-11-07). 지금의 나가기 경고 창으로 버티고, 문제가 보이면 옮긴다.
- 처리방침 변경 = 배포 즉시 전원 재동의. **배포 시점은 사용자가 정한다.**

## 8. 제약

- 하위 페이지 톤·버튼·반응형 규칙(CLAUDE.md) 그대로. hover 확대·떠오름 금지, `transition-all` 금지.
- Workers 무료 CPU 10ms — 상세 페이지에 무거운 일 추가 금지(포스터 표시는 URL 하나 읽기).
- 링크는 `@/components/shared/link`.
- 쿠키로 인증하는 새 Route Handler면 `isSameOrigin()`.
- DB 변경은 migration으로, main 푸시 = 자동 적용 — 칸 단위 GRANT 표에 `(count)` 집계 금지.
- `.claude/rules/posters.md`·`projects.md`·`nav.md`·`privacy.md`·`admin.md` 갱신.

## 9. 검토 뒤 정한 것 (모두 내 판단)

- **한도**(사용자 결정 2026-11-07): AI + 직접 올린 것 **합쳐서 프로젝트당 5개**(`POSTER_LIMITS.perProject` 3 → 5, `poster_limit` 트리거도 5). 옛 3개는 DB 사정이 아니라 목록 길이용 임의 숫자였고, AI 비용은 하루 횟수 제한이 막는다. 걸리는 건 그중 1개.
- **올리기 경로**: `/api/upload` 재사용 안 함. 포스터 전용 경로(쿠키 인증 → `isSameOrigin()`, PNG·JPEG·WebP만, Cloudinary `dshs/posters`, 포스터 권한 확인 뒤). GIF·SVG 거절.
- **등록 폼에서 올릴 때**: 그림은 Cloudinary에 먼저 올라가고, 프로젝트 저장이 성공한 뒤 포스터 행을 만들고 건다. 저장 실패·이탈로 남는 Cloudinary 파일은 이번엔 정리 안 함(아이콘 업로드와 같은 처지).
- **AI 포스터 걸기**: 일반 해상도 PNG(인쇄용 확대 안 씀), 서버 액션에서 바로(동기). 실패·429면 "잠시 뒤 다시 걸어 주세요"만. 그림 그리는 중(`art_job_id` 대기)이면 걸기 버튼 꺼짐. 걸기 전용 하루 상한은 안 둠(내보내기와 같은 처지, 문제 생기면 추가).
- **"걸린 뒤 고쳤어요"**: 걸 때 시각을 `projects`에 같이 남기고(예: `poster_hung_at`) 그 포스터의 `updated_at`과 비교.
- **파일 정리**: 그림은 프로젝트에 딸린다 — 팀원이 올린 것도 팀원 탈퇴로 안 지움. 프로젝트 삭제(소유자 탈퇴 CASCADE 포함) 때 그 프로젝트 포스터 그림·걸린 PNG를 Cloudinary에서 최선 노력으로 지움. 비공개 전환은 숨김만. 다시 걸거나 내리면 옛 걸린 PNG(AI용)는 지움.
- **익명 프로젝트**: 걸린 포스터에 작성자 정보를 붙이지 않는다. 올리기 칸에 "포스터에 이름을 넣으면 익명이 풀려요" 한 줄.
- **권유 카드·빠른 상세**: 포스터 권유는 `DomainNudge`가 빠른 상세에서 하는 그대로 따른다. 우선순위 판정은 상세 화면이 이미 계산하는 값으로.
- **홍보 한 줄의 "내 프로젝트"**: 누를 때 읽는다(미리 안 읽음). 범위 = 내가 고칠 수 있는 공개 프로젝트(`my_project_ids` + 팀원으로 들어간 것).
