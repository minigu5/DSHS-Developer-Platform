# AI 포스터 만들기 — 설계 (2026-11-05)

> 브레인스토밍 결과 문서. 구현은 다음 세션에서 이 문서 → `superpowers:writing-plans` 순서로.
> 참고 자료: `docs/superpowers/specs/2026-11-05-ai-poster/` (공통 띠 CSS, 실험 스크립트, 실험 결과 그림)

> **2026-11-06 개정 — 그림은 이미지 AI, 글·배치는 HTML(섞기)** (사용자 결정). Gemini가 SVG로 그린 그림보다 이미지 AI 그림 + HTML 글자 시안이 낫다는 평가("와씨 포스터가 네가 만든 것보다 나은데"). 이미지 AI에 포스터를 통째로 그리게 하면 한글이 깨져서(§10-2) 글자는 HTML이 맡는다. 바뀐 곳: §2 비목표, §3, §5, §5-1(새로), §6, §8, §10-2(새로), §11. 시안: `~/Desktop/대곽나루-포스터/AI-실험/이미지생성/섞기-시안-1.png`.

## 1. 의도와 이유

대곽 개발자 플랫폼에 프로젝트를 올린 학생이 **학교에 붙일 홍보 포스터를 쉽게 만들게** 하고, 그 포스터마다 **"대곽 개발자 플랫폼에서 만나요" 띠 + QR**이 붙어 사이트로 사람을 데려오게 한다.

- 처음 생각은 "QR과 정해진 가로 띠만 나눠 주기"였지만, 사용자 판단으로 그건 "날먹"(학생이 결국 포스터를 처음부터 만들어야 함)이라 버렸다.
- 프로젝트 정보로 틀에 글자만 채워 넣는 자동 포스터도 버렸다(사용자: "텍스트 내용만 들어가서 뭐해"). 좋은 포스터는 그 프로젝트만의 아이디어에서 나온다(대곽나루 포스터: 고래 = 컴퓨터 18대, 3D 프린터 포스터: "가지러 갈 때만 가요").
- 그래서 **AI가 프로젝트 정보로 HTML 포스터를 대충이라도 만들어 주고, 학생이 "제목 더 크게"처럼 AI에게 다시 부탁해서 고치는** 기능으로 정했다(사용자 결정). HTML이라 고칠 수 있다는 게 핵심.

## 2. 목표 / 비목표 / 반목표

**목표**
- 프로젝트 상세에서 버튼 한 번으로 AI가 A4 세로 포스터(HTML)를 만든다.
- 대화로 고친다: 학생이 부탁 → AI가 HTML 전체를 다시 줌 → 미리보기 갱신.
- 만든 포스터는 **저장**되어 다음에 이어서 고칠 수 있고, **새로 만들 수도** 있다(제한 있음 — 사용자 결정).
- 결과를 **PNG·PDF로 받는다**. 맨 아래 플랫폼 띠 + QR은 항상 붙어 있다.

**비목표**
- 직접 글자를 클릭해 편집하는 에디터(사용자 결정: AI에게 다시 부탁하는 방식만).
- 포스터를 남에게 공개·프로젝트 페이지에 전시(내 판단: 만든 사람들만 본다).
- 이미지 AI가 포스터 전체(글자 포함)를 그리는 것 — 한글이 깨진다(§10-2). 이미지 AI는 **글자 없는 그림 한 장**만 그린다.

**반목표 (돌아가도 실패로 보는 것)**
- AI가 **없는 사실을 지어낸 포스터**(가짜 주소·숫자·기능). 실험에서 Gemini가 `daegwak-naru.hs.kr` 같은 가짜 주소를, GLM이 "Lab Access Gateway" 같은 가짜 영문명을 만들었다 — 반드시 막아야 한다.
- 플랫폼 띠·QR이 빠지거나, AI가 띠 영역을 덮는 포스터.
- AI가 만든 HTML이 사이트 화면에서 그대로 실행되는 것(XSS).
- 무료 키 할당량을 한두 명이 다 써 버려 나머지가 못 쓰는 상황.

## 4. 화면 흐름

1. **입구**: 프로젝트 상세(`src/app/(nav)/projects/[id]/(detail)/page.tsx`)에 "포스터 만들기" 버튼. 보이는 조건은 기존 `canEdit`(소유자·팀원·개발자 계정, 익명 프로젝트는 `my_project_ids()`로 본인 확인)와 같다.
2. **포스터 목록** `/projects/[id]/poster`: 이 프로젝트의 저장된 포스터(최대 3개) 썸네일 + "새로 만들기". 3개가 차면 하나를 지워야 새로 만들 수 있다.
3. **만들기/고치기 화면** `/projects/[id]/poster/[posterId]` (경로는 빌더 재량):
   - 왼쪽(모바일은 위) 미리보기: A4 비율, **격리된 iframe** 안에 AI HTML, 그 아래 우리 띠.
   - 오른쪽(모바일은 아래) 대화: 지금까지의 부탁 기록 + 입력칸 + 보내기. 처음 만들 때는 선택 입력 "강조하고 싶은 점"(비워도 됨).
   - 생성 중(실험상 1회 80~90초): 진행 표시 + "1~2분 걸려요" 안내. 실패하면 친절한 문구와 다시 시도.
   - "되돌리기"(직전 버전으로) — 내 판단. 버전은 최근 몇 개만 보관(개수는 빌더 재량, 5개 정도).
   - "PNG로 받기" / "PDF로 받기".
4. 하위 페이지 공통 톤(`PageHero compact`, `loading.tsx` 뼈대, route group 규칙, 모바일 `px-6`)을 따른다. 보호 라우트(`src/middleware.ts`)에 `/projects/[id]/poster` 추가.

## 5. AI 연동 (Gemini)

- **키**: `GEMINI_API_KEY` — 서버 전용 비밀값(`.env.local`, Cloudflare `wrangler secret put`). 사용자 개인 Google 계정에서 발급한 무료 키. 브라우저로 절대 내려보내지 않는다.
- **호출 위치**: 서버(Route Handler 또는 서버 액션). 키·권한·횟수 검사가 있으므로 서버에 둔다. Workers 무료 CPU 10ms는 응답을 기다리는 시간과 무관하지만, 큰 JSON 파싱·HTML 정리에 CPU를 쓰므로 가볍게 유지.
- **긴 응답**: 1회 80~90초. 연결이 끊기지 않게 스트리밍(`streamGenerateContent`)으로 브라우저에 진행 신호를 흘리거나, 작업을 시작만 하고 결과를 나중에 받는 방식 중 빌더가 고른다. Cloudflare에서 오래 걸리는 요청이 실제로 유지되는지 배포 환경에서 확인할 것.
- **모델**: 2026-11-05 실험 기준 무료 키로 쓸 수 있었던 건 `gemini-3.5-flash`뿐(3.7·3.8 Flash는 수요 폭주 503, 3.1 Pro는 무료 할당량 없음 429, 2.5 Flash는 새 사용자 404). → **모델 목록을 설정값으로 두고 순서대로 시도**(503·404면 다음 모델). 구현 시점에 `GET /v1beta/models`로 다시 확인.
- **오류**: 429(할당량)·503(붐빔)은 "지금 AI가 붐벼요, 잠시 뒤 다시"로, 사용자 하루 횟수는 깎지 않는다(내 판단).

### 프롬프트 (출발점: `2026-11-05-ai-poster/spike-reference.mjs`의 `SYSTEM`)
실험 프롬프트에 아래를 더 세게 넣는다.
- 출력은 ```html 블록 하나. 캔버스 **정확히 1240×1518px**, 넘치면 안 됨(아래 236px는 우리 띠 자리라 AI 영역 밖).
- **주소·숫자·기능·영문 이름을 지어내지 말 것.** 주소가 필요하면 우리가 준 실제 주소만. (가짜 주소를 막는 가장 확실한 방법은 프롬프트에 "주소는 쓰지 말 것, 띠에 QR이 있음"으로 아예 금지하는 것 — 빌더가 둘 중 고름.)
- 글은 헤드라인 한 줄(두 줄까지) + 서비스 이름. 기능 알약·배지 남발 금지(실험에서 Gemini가 알약 5개를 붙임).
- 큰 그림은 직접 그리지 말고 `<img src="ART">` 자리 하나로 비워 두고, 그 자리에 들어갈 그림을 §5-1 형식으로 주문한다(작은 장식 도형만 인라인 SVG 허용).
- 크림·베이지·금색·어두운 바탕, 포스트잇·손글씨 화살표·이모지 금지(사용자 취향 — 포스터 작업에서 반복 피드백).
- 외부 리소스는 Google Fonts만, `<script>` 금지.
- 고치기 요청에는 **HTML 전체**를 다시 준다. 대화 기록은 토큰을 아끼려고 "시스템 프롬프트 + 프로젝트 정보 + 최신 HTML + 최근 부탁 몇 개"로 줄여 보낸다(빌더 재량).

### 5-1. 그림 (Workers AI, 2026-11-06)
- Gemini 응답 = ```json 블록 `{"art":{"prompt":"<영어>","width":W,"height":H}}` + ```html 블록. 고치기 응답에서 json 블록이 없으면 그림은 그대로 둔다.
- **그림 비율은 Gemini가 정한 `ART` 자리 크기로 API에 요청한다**(사용자 지적). 서버가 비율은 지키고 넓이를 상한(무료 할당량을 아끼는 크기 — 계획 Task 1에서 측정)까지 줄이고 16의 배수로 맞춘다. 화면에선 `object-fit: cover`로 자리를 채운다.
- 그림 프롬프트 규칙: 글자·숫자·로고 금지, 밝은 바탕, 흰 여백이 필요한 쪽을 적기. 모델: `@cf/black-forest-labs/flux-2-klein-9b`(1024×768 한 장 ~1,360 neurons). 호출은 Worker의 `AI` 바인딩.
- 받은 그림(base64)은 Cloudinary(`dshs/posters` 폴더)에 올리고 URL만 저장한다. 저장된 HTML에는 늘 `ART` 표시만 있고, 보여 줄 때 URL로 바꾼다(Gemini에 큰 data URI를 보내지 않음).
- 학생이 "그림 다시 그려 줘"를 버튼으로 누를 수 있다(Gemini를 거치지 않고 같은 프롬프트로 다시 그림 — 글 횟수 안 씀).
- 할당량은 계정 전체 공유(00:00 UTC = KST 09:00에 채워짐). 다 쓰면 "오늘 그림 할당량이 다 찼어요, 오전 9시에 다시 채워져요" — 글 수정은 계속 된다.

### 보내는 정보 (공개 정보만)
이름, 한 줄 설명/설명 요약, 종류, 플랫폼, 실제 주소(`url`), 아이콘 URL(그림에 `<img>`로 쓸 수 있게 — 빌더 판단), 학생이 입력한 부탁 문구. 비공개 프로젝트는 만든 사람만 쓰는 기능이라 보내도 되지만, 처리방침에 "포스터 만들기를 쓴 프로젝트의 정보"로 적는다. 이메일·실명·팀원 정보는 보내지 않는다.

## 6. 보안 — AI가 만든 HTML 다루기

- 미리보기는 **`<iframe sandbox srcdoc>`**, `allow-same-origin` 절대 주지 않는다(우리 쿠키·저장소에 못 닿게). 사이트 DOM에 직접 넣지 않는다.
- 저장 전에 서버에서 `<script>`·`on*=` 속성·`javascript:` URL을 걷어낸다(Workers에는 DOMParser가 없으니 가벼운 정리 + sandbox가 최종 방어).
- srcdoc 안에 CSP `<meta>`: 스크립트 없음, 스타일 inline + Google Fonts, 폰트 gstatic, 이미지 `res.cloudinary.com`·data.
- `project_posters`는 RLS를 켜고 사용자 키 정책을 두지 않는다(사용자 키로 못 읽고 못 씀). 읽기·쓰기는 서버가 권한(§8)을 확인한 뒤 서비스 키로만 — Gemini 키·횟수 검사가 어차피 서버에 있다.
- 사이트 보안 헤더(`X-Frame-Options: DENY`)는 우리 페이지를 남이 iframe에 넣는 걸 막는 것이라 srcdoc iframe과는 충돌하지 않는다 — 확인만.

## 7. 플랫폼 띠 + QR

- 띠는 **우리 코드가 그린다**. AI 영역(1240×1518) 아래에 1240×236 띠를 붙여 전체 1240×1754(A4 비율).
- 디자인은 `2026-11-05-ai-poster/dshs-band.css` 그대로(밝은·어두운 두 가지, 이번 포스터들에 쓴 것). 내용: 플랫폼 로고(`public/logo.svg`), "대곽 개발자 플랫폼에서 만나요", "DSHS Developer Platform · 학생이 만든 프로그램을 한곳에서", `dshs.dev`, "‘{프로젝트 이름}’ 검색 또는 QR", QR.
- QR 주소: `https://dshs.dev/projects/{id}`. 브라우저에서 만든다(보안 무관 표시 작업은 브라우저로 — CLAUDE.md CPU 원칙). 라이브러리는 빌더 재량(실험에선 `qrcode` 1.5.4).
- 밝은/어두운 띠 선택은 학생이 고르게 하거나 AI 바탕색으로 자동 결정 — 빌더 재량.

## 8. 저장·권한·제한

- **새 표** (이름은 빌더 재량, 예: `project_posters`): 프로젝트, 만든 사람, 현재 HTML, 최근 버전 몇 개, 대화 기록(줄인 형태), 띠 색, 생성·수정 시각.
- **권한**: 읽기·쓰기 모두 그 프로젝트를 수정할 수 있는 사람(소유자·`team_members`·관리자). RLS로 막는다. 기존 규칙 지킬 것 — `public.users.email` 말고 `auth.jwt() ->> 'email'`, `(select auth.uid())`, `is_admin()`. 익명 프로젝트는 `author_id`를 사용자 키로 못 읽으니 SECURITY DEFINER 함수나 `my_project_ids()` 활용.
- **새 포스터는 프로젝트마다 하루(KST) 1개**(사용자 결정 2026-11-06, 지웠다 다시 만들어도 막음). 고치기는 아래 글 한도대로.
- **제한**(내 판단, 숫자는 바꿀 수 있음): 프로젝트당 저장 3개, **사람당 하루 AI 요청 20번**(만들기·고치기 모두 1번), **그림은 따로** 사이트 전체 하루 상한(Workers AI 무료 10,000 neurons ÷ 한 장 비용, 여유 1장 — Task 1에서 정함)·사람당 하루 5장. 무료 키는 사이트 전체가 공유하므로 **사이트 전체 하루 상한**도 둔다(값은 구현 시 Gemini 무료 한도를 확인해 정함). 횟수는 DB에서 센다(서버 시각 기준, 브라우저 못 바꾸게).
- 차단된 사용자(`private.is_banned`)는 못 쓴다.
- 탈퇴 시 함께 지워지게(`withdraw_account` CASCADE 경로 확인).

## 10-0. 공개 순서 (사용자 결정, 2026-11-05)
- **1단계 = 관리자(개발자 계정, `is_admin()`)만**. 버튼·페이지·서버 액션·RLS 모두 관리자 검사(기능 플래그 하나로 묶어 2단계에서 풀기 쉽게). 이 단계에선 **처리방침을 고치지 않는다**(관리자 본인 정보만 오가므로 재동의 팝업 없음).

## 10-1. 검토에서 나온 질문에 대한 결정 (내 판단, 2026-11-05)
- **공개 프로젝트만**: 비공개 프로젝트는 QR(`/projects/{id}`)이 외부인에게 404라 포스터가 쓸모없고, 비공개 정보를 Google로 보내지 않게 된다. 버튼 노출·서버 검사 모두 `visibility = 'public'`. 공개였다가 비공개로 바뀌면 기존 포스터는 **지우지 않고 숨김**(다시 공개하면 보임) — 별도 후크 없이 읽을 때 검사.
- **포스터는 프로젝트 소유**: 수정할 수 있는 사람(소유자·팀원·관리자)이 함께 보고 고친다. `created_by`는 기록용(탈퇴 시 NULL), 포스터는 프로젝트가 지워질 때만 함께 지워진다. 동시에 고치면 마지막 저장이 이긴다(충돌 처리 없음).
- **횟수**: "하루"는 **KST 자정** 기준. 요청 시작 때 DB 트랜잭션으로 1회 **예약**(상한 넘으면 거절 — 동시 요청에도 안 샘), 실패하면 **돌려줌**. 돌려주는 실패: 429·503·시간 초과·안전 필터 차단·HTML을 못 찾은 응답. 서버는 **내용 문제로 자동 재시도하지 않는다**(모델 폴백은 503·404에서만). 잘린 HTML은 그대로 보여 주고 학생이 다시 부탁.
- **AI 출력 검사**: 거부하지 않고 보여 준다. 서버는 §6의 정리만 한다. 띠 침범은 구조로 막는다 — AI HTML은 1240×1518 고정 크기 iframe 안에만 있어 넘치는 부분은 잘리고, 띠는 iframe 밖 우리 요소.
- **사이트 전체 상한 도달**: 선착순으로 막고 "오늘 사이트 전체 AI 사용량이 다 찼어요, 내일 다시"를 보여 준다. 학생별 배분은 사람당 상한으로 충분. `/admin`에 오늘 사용량 한 줄은 있으면 좋음(필수 아님).
