## 🔏 개인정보 처리방침·동의·철회 (`/privacy`, 2026-10-25)
- **페이지** `/privacy`(`src/app/(nav)/privacy/page.tsx`, 비로그인 열람 가능): `PageHero`(section=`privacy`, 무채색 zinc) → 로그인했으면 "내 동의 기록" 카드(`ConsentStatus`, 브라우저가 읽음 — 페이지는 `force-static`이라 본문 마크다운도 빌드 때 변환; 동의 일시 KST·버전·지난 기록 + "동의 철회하고 탈퇴") → `ReadingSurface`에 본문. 푸터 "이 사이트" 칸·로그인 화면에 링크. 사용자 요청: 팝업 동의, 거부 시 로그아웃, 동의 일시 기록, 철회 가능.
- **본문** `src/lib/privacy/policy.ts`(마크다운 문자열, `Markdown`으로 렌더): **실제 코드가 하는 일을 그대로 적는다** — 수집 항목·공개 범위·위탁(Supabase/Cloudflare/Cloudinary/Google)·국외 이전·쿠키·파기·구제기관. 로그인하지 않은 방문의 `project_clicks.ip_hash`(IP+UA의 SHA-256, 소금 없음)도 항목에 적혀 있다 — 새 수집·위탁이 생기면 여기도 고칠 것. **본문을 고쳐도 동의 창은 다시 안 뜬다**(2026-11-08 사용자 결정 — 법은 처리방침 변경 시 공개·공지만 요구, 재동의는 수집·이용 같은 개별 동의에만 필요): 동의받는 버전 `PRIVACY_CONSENT_VERSION`(`src/lib/privacy/version.ts`)은 **손으로만** 올린다 — 서비스에 꼭 필요하지 않은 정보를 새로 모으거나 새 목적으로 쓸 때, 제3자 제공(남이 자기 목적으로 씀)·민감정보·마케팅. 위탁 업체·해외 서버 추가, 공개 범위 축소, 문구·오탈자는 올리지 않고 `PRIVACY_EFFECTIVE_DATE`(policy.ts 시행일)만 고친 뒤 시행 전에 공지사항에 올린다. 예전에는 시행일+본문 해시로 자동이라 한 글자만 고쳐도 전원 재동의였다(11-08 하트 비공개 전환까지) — 그 마지막 값 `2026-11-08-1f658b03`을 그대로 고정했다. 새 값은 `YYYY-MM-DD`(DB CHECK는 날짜 또는 날짜-16진수8자리). 담당·문의처는 "신민규"·`PRIVACY_CONTACT_EMAIL` = `seong381400@gmail.com`(2026-10-31 사용자 지정). 시행일 2026-11-05 — 리뷰·별점을 댓글·하트(즐겨찾기 공개)로 바꾸며 문구 수정, 전원 재동의(사용자 동의). **시행일 2026-11-07 — AI 포스터를 학생에게 열며**: 위탁 표에 Google LLC(Gemini API — 공개 프로젝트 정보·공개 저장소 내용·부탁 문구, 무료 API라 학습에 쓰일 수 있음), Cloudflare에 "포스터 그림·파일 만들기", Cloudinary에 포스터 그림, 1번 표에 홍보 포스터, 7번 파기에 포스터 그림. 학교 Mac mini는 교내 기기이고 영어 그림 설명만 받아 위탁으로 적지 않았다. 배포 시점은 사용자가 정함. **시행일 2026-11-08 — 즐겨찾기를 본인·관리자만으로**: "누구에게 보이나요?"에서 즐겨찾기를 공개 목록에서 빼고 "나와 관리자만, 다른 사람에게는 하트 수만"(사용자 동의, 전원 재동의). 법률 검토를 받은 문서가 아니라 초안.
- **동의 기록** `public.privacy_consents`(`user_id`, `policy_version`, `consented_at timestamptz`, UNIQUE(user_id, policy_version)): 버전마다 한 줄, 처음 동의한 시각을 유지(upsert ignoreDuplicates). RLS SELECT 본인만, 쓰기 정책 없음 — 서버 액션이 `getUser()` 확인 후 `createAdminClient()`로만 기록(시각을 브라우저가 못 바꿈). IP·User-Agent는 저장하지 않는다. `policy_version`은 `YYYY-MM-DD` 또는 `YYYY-MM-DD-<해시8>`(CHECK). `docs/21-supabase-privacy-consents.sql`(최종 형태) = migration `20261025090000_privacy_consents.sql` + `20261025120000_privacy_consents_version_hash.sql`(CHECK 확장) — 둘 다 운영 적용 완료. 후자는 운영 DB에 서브도메인 작업의 `20261025100000_subdomains`가 로컬에 없어서 `db push`가 막혀 `supabase db query --linked -f`로 적용했다(기록 표에는 없지만 다시 push해도 멱등).
- **팝업** `PrivacyGate`(`src/components/privacy/privacy-gate.tsx`, 클라이언트, **루트 레이아웃**): 로그인했는데 현재 버전 동의가 없으면 shadcn `Dialog`가 뜬다(예전 버전에 동의한 적이 있으면 제목이 "개인정보 처리방침이 바뀌었어요"). 동의 액션은 팝업이 보여 준 버전을 같이 보내고(`acceptPrivacyPolicy(seenVersion)`), 그사이 동의 버전이 올랐으면 거절한다 — 읽지 않은 글에 동의시키지 않는다. 닫을 수 없다(`open` 제어 + `onOpenChange` 무시, X 없음). "동의하고 계속"(`acceptPrivacyPolicy`) / "동의하지 않고 로그아웃"(`declinePrivacyPolicy`). `/privacy`에서는 읽을 수 있게 안 띄움. 온보딩 화면에서도 뜬다(루트 레이아웃). 서버에서 쿠키를 읽지 않으므로 홈·목록 ISR을 깨지 않는다 — 판정은 브라우저 supabase 클라이언트로 `privacy_consents`를 조회(AuthButtons와 같은 방식). **UI에서만 막는다**: 서버 액션·API는 동의 여부를 검사하지 않음.
- **쿠키 캐시** `ds_privacy=<버전>`(운영 이름은 `__Host-ds_privacy` — 2026-11-12 감사, 학생 주소 JS가 `Domain=.dshs.dev`로 심어 동의 창을 건너뛰게 못 하게. 처리방침 본문의 `ds_privacy` 표기는 그대로)(1년, **httpOnly 아님** — 클라이언트가 읽고 조회를 건너뜀): `src/middleware.ts`가 로그인 사용자의 쿠키가 현재 버전과 다르면 DB를 보고 동의했을 때만 심는다(`ds_onboarded`와 같은 방식). 동의 버전을 올리면 자동 무효. 동의 전 사용자는 쿠키가 없어 페이지마다 조회가 한 번 더 간다(일시적).
- **거부** `declinePrivacyPolicy`: `signOut` + `ds_privacy`·`ds_onboarded` 쿠키 삭제. 한 번도 동의한 적 없고 닉네임도 없는 **새 계정은 함께 삭제**(쓴 글이 없고 개인정보를 쥘 이유가 없음). 이미 쓰던 계정은 남긴다.
- **철회 = 탈퇴** `withdrawAccount(confirmText)`(`src/lib/privacy/actions.ts`, 라우트 그룹 밖): 확인 칸에 "탈퇴"를 직접 입력해야 한다(`WithdrawButton`). DB 쪽은 `public.withdraw_account(uuid)`(SECURITY DEFINER, **EXECUTE는 `service_role` 전용**) 한 트랜잭션: 다른 사람 프로젝트의 `team_members`·`allowed_users`에서 내 이메일 제거 → `guide_revisions.author_email`을 `withdrawn-<무작위>`로 바꿈(내용은 위키라 남김) → `project_clicks`의 내 행 삭제(`user_or_ip_required` CHECK 때문에 `user_id` SET NULL이 실패함) → `auth.users` 삭제(users·프로젝트·프로젝트 댓글·하트·팁·댓글·좋아요·해줘·공지·동의 기록 CASCADE). 반환된 이미지 URL(아바타·프로젝트 아이콘·팁 커버)과 RPC 전에 챙긴 내 프로젝트 포스터 그림(`posterImageUrlsOf`)은 `cloudinaryPublicId`(`src/lib/privacy/format.ts`, 우리 계정의 `dshs/` 폴더만)로 public_id를 뽑아 Cloudinary에서 최선 노력으로 삭제. 팀 프로젝트의 소유자가 탈퇴하면 프로젝트가 팀원에게도 사라진다(다이얼로그가 경고). 함수 수정은 새 migration으로 — 롤백되는 트랜잭션 시험은 `supabase db query --linked -f`로(운영에서 확인함).
- **관리자 차단 기록**(2026-11-05, `.claude/rules/admin.md`): 처리방침 1번 표에 "사이트 관리"(프로필 수정 시각, 차단 기록) 행, 2번에 "차단 중 탈퇴하면 이메일 해시·끝나는 날만 차단이 끝날 때까지", 7번 파기에 차단 기록 한 줄을 넣었다. `withdraw_account`가 그대로 처리하고 `users` 삭제 트리거가 `admin_actions`의 id를 지운다.
