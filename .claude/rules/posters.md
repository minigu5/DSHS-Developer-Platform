## 걸기·올리기·홍보 길 (2026-11-07 사용자 결정)
- **상세 페이지 오른쪽 옆칸 맨 위에 걸린 포스터 1장**(`PosterShowcase`, 공개 프로젝트만 — `showcaseVisible`, 비공개 허용 사용자에게도 안 보임). **마우스를 올려도 안 커진다**(hover 확대 금지 유지 — 사용자 결정), 누르면 `Dialog`로 크게(창은 `right-0 left-0 mx-auto w-fit` — 공용 창의 left:50% + 너비 auto는 폭이 화면 절반으로 묶여 포스터가 작았다, 2026-11-07). 누르고 싶게: 테두리 색만 진해짐·`cursor-zoom-in`·"크게 보기" 알약. AI 포스터면 "AI로 만든 포스터" 알약.
- **홍보 길** = 남의 상세에서 크게 보기 창 아래 "이 포스터, 내 프로젝트로도 만들 수 있어요 →" → `/posters/start`(보호 라우트): 내가 고칠 수 있는 공개 프로젝트(`my_project_ids` + 팀원) 0개면 `/projects/new`, 1개면 그 수정 화면의 포스터 칸(`/projects/<id>/edit?poster=list`), 여럿이면 고르기(`posterStartTarget`). 공지·홈 알림은 안 함. 첫 포스터는 사용자가 주인들에게 직접 부탁(관리자 대신 걸기 없음).
- **종류** `project_posters.kind`: `ai`(html) / `upload`(직접 만든 그림 `image_url`, CHECK). 개수 **AI+올림 합쳐 프로젝트당 5개**(`poster_limit`, 옛 3개는 임의 숫자). "새 포스터 하루 1개"는 2026-11-08 삭제(아래 「권한·제한」).
- **걸린 포스터** = `projects.poster_id`(FK SET NULL)·`poster_image_url`·`poster_is_ai`·`poster_hung_at`(migration `20261107120000`). anon/authenticated는 `poster_image_url`·`poster_is_ai`만 읽힘(`PROJECT_COLUMNS`), 사용자 키로는 네 칸 다 못 바꿈(`projects_guard_owner`). `poster_id`가 비면 트리거 `projects_poster_clear`가 나머지를 비운다(포스터 삭제·내리기 둘 다). 쓰기는 `setHungPoster`(`hang-db.ts`, 서비스 키, 이전이 AI PNG면 Cloudinary에서 지움).
- **걸기** `hangPoster`/`unhangPoster`(`hang.ts`, 권한 `getBandAccess` = 포스터 화면과 같음): 올린 그림은 그 주소 그대로, AI는 `renderPosterFile`(`render.ts`, 내보내기와 공용)로 1240×1754 PNG를 찍어 `dshs/posters`에 — **8~9초라 뒤에서 찍는다**(2026-11-07 사용자 "왜 이렇게 오래" → 사용자 선택): `startHangingAi`가 그림 주소 없이 먼저 걸고(이전 AI PNG는 바로 지움) `ctx.waitUntil`로 찍어 `finishHungPng`가 `poster_id`·`poster_hung_at`이 그대로일 때만 주소를 붙인다(그사이 바꿨으면 방금 찍은 PNG를 지움). 그동안 상세엔 안 보이지만 포스터 화면은 바로 "걸려 있어요" + 작게 "상세 페이지 그림 만드는 중…"(2026-11-07 사용자 또 "왜 이렇게 오래" — 기다릴 일이 아니라서 걸린 걸로 보임, 2초마다 다시 읽음)·2분 넘게 없으면 "포스터를 못 찍었어요 · 다시 걸기". 느린 이유는 Browser Rendering이 크롬을 띄워 HTML을 찍기 때문(글꼴 기다림 2초 포함). 로컬 dev처럼 Workers 문맥이 없으면 기다렸다가 끝낸다. 그림 그리는 중이면 못 건다(`canHangPoster`) — HTML에 `ART` 자리가 있는데 `art_url`도 `art_job_id`도 없으면(그림 생성 실패) 빈 그림 자리로 걸리니 그때도 못 건다. 걸린 뒤 고치면 "걸린 뒤 고쳤어요 · 다시 걸기"(`hungIsStale`, 자동으로 다시 안 찍음).
- **올리기** `POST /api/posters/upload`(multipart `projectId`·`file`·`hang`): `isSameOrigin` → `content-length`가 10MB+64KB(multipart 머리 몫)를 넘으면 본문을 읽기 전에 413 → `getBandAccess` → 파일 10MB → 앞 12바이트 `sniffImageType`(PNG·JPEG·WebP) → Blob 그대로 Cloudinary → 행 → `hang=1`이면 걸기. 409 `poster_limit`(방금 올린 그림은 지움). 걸기만 실패하면 `{ ok: true, hung: false }` — 포스터 화면 버튼·등록 폼이 "올렸지만 걸지 못했어요" 토스트(`POSTER_UPLOADED_NOT_HUNG`). 올린 그림은 **바로 걸리고 관리자가 나중에 검토**(`/admin` 「걸린 포스터」, 사용자 결정).
- **들어가는 길**: 수정 폼 「홍보 포스터(선택)」 카드(새 등록 폼엔 없음 — 2026-11-07 사용자 요청, 등록 전엔 제대로 안 돼서 "파일 골라 두면 저장 뒤 올리기"(`PosterFileField`, 삭제)·"등록한 뒤 AI로 만들기"를 뺐다), **상세 옆칸의 빈 포스터 칸** `PosterSlot`(아래 「상세에서도 같은 칸」), 수정 폼 카드의 "홍보 포스터 만들기"(공개 프로젝트, 2026-11-07 사용자 요청 — 옆 칸을 연다). 포스터 화면·`/posters/*`에선 메뉴 "프로젝트 등록"이 켜짐(`src/lib/nav-active.ts`). 탭 분할은 쓰지 않는다(사용자 "최악").
- 지우기(`deletePoster`)도 `getBandAccess` — 올린 그림·AI 그림(`art_url`)·걸린 AI PNG를 Cloudinary에서 같이 지운다. 프로젝트 삭제·탈퇴·관리자 지우기(`/admin` `deleteOne`) 때는 `posterImageUrlsOf`(`cleanup.ts`)로 CASCADE 전에 주소를 챙겨 지운다(`cloudinaryPublicId`가 `dshs/posters/`도 인식).
- **올린 그림 행은 AI 경로에서 없는 것**: `guardPosterRequest`(ask·redraw·export·art·job)·스튜디오 데이터 `getPosterStudio`(`panel.ts`)·서버 액션 `posterWithAccess`(되돌리기·띠)는 `kind !== 'ai'`면 404 — 올린 그림 행에서 AI 경로가 돌지 않게(2026-11-07, 원래는 "하루 1개" 우회 막기였다).

## 페이지 구성 (2026-11-06 사용자 결정 — 띠 받기가 기본, AI 포스터는 부가)
- **포스터 칸 = 프로젝트 수정 화면의 옆 칸**(`PosterSheet`, 2026-11-07 사용자 결정 — "수정에서만 들어가는 페이지가 온전한 페이지로 있는 게 이상하다"; 시안 4개 중 오른쪽에서 나오는 칸, 휴대폰은 화면 꽉. 사용자가 말한 "팝업 금지"는 브라우저 새 창 뜻이라 페이지 안 창은 괜찮다). 수정 화면 `page.tsx`가 공개 프로젝트일 때만 둔다. 상태는 주소 `?poster=list|<포스터 id>` 하나(`poster-sheet-nav.ts`) — `history.pushState`라 서버를 다시 부르지 않아 폼에 쓰던 내용이 그대로고, 연 만큼 기록을 쌓아 휴대폰 뒤로 가기가 칸을 닫는다(닫기 버튼은 쌓은 만큼 `history.go(-n)`, 주소로 바로 들어왔으면 `replaceState`). 칸을 닫으면 목록에서 뭔가 바꿨을 때만 `router.refresh()`로 폼 카드의 걸린 포스터 그림을 새로 읽는다. 깜빡임 줄이기(2026-11-07 사용자 "창이 생겼다 없어졌다 할 때 깜빡"): 목록은 수정 화면이 열릴 때 미리 받아 칸에 들고 있다가(열 때마다 뒤에서 새로 읽음), 카드에 마우스를 올리거나 초점이 가면 만들기 화면 데이터를 미리 받아 열 때 한 번 쓴다(`studioPrefetch`). 닫히는 0.2초 동안은 보던 화면을 그대로 둔다(`shown`). 닫을 때 화면 전체가 한 번 어두워지던 건 배경(0.15초)이 칸(0.2초)보다 먼저 끝나 원래 진하기로 튀어 오른 것 — 둘 다 `duration-200` + `data-closed:fill-mode-forwards`(tw-animate 기본 fill-mode가 none이라 끝나면 처음 모양으로 돌아감, rAF로 투명도 기록해 확인). 데이터는 서버 액션 `getPosterList`·`getPosterStudio`(`panel.ts`, 예전 페이지가 하던 권한 확인·`settleArtJob`·`settlePosterJob` 그대로). 칸 맨 위 "포스터는 누르는 즉시 저장돼요. 프로젝트의 “저장하기”와 따로예요." 스튜디오는 칸 폭으로 나눈다(`@container`·`@3xl:` — 화면 폭 `lg:`가 아님). **크기**(2026-11-07 사용자 "레이아웃이 너무 크다"): 칸 960px, 미리보기 폭 = 화면 높이에 포스터+띠가 다 들어가는 폭(`PREVIEW_COLUMN` = `clamp(280px,(100dvh-16rem)×0.707,520px)`, 1440×900에서 스크롤 없음), 대화가 나머지 폭. 미리보기 아래 "이 포스터 걸기"(목록의 걸린 상태를 받아 `PosterStudioHang`, 목록을 못 받았으면 숨김)·PNG·PDF, 그 아래 띠 세그먼트. 스타일 5개는 `ToggleChip` 한 줄 + 고른 것 설명 한 줄. 목록은 `@2xl:` 4열(좁으면 2열), 띠 받기 카드 p-5·제목 text-lg. **가볍게**(사용자 "팝업이 너무 헤비"): `PosterPreview`는 iframe을 `requestIdleCallback`(없으면 250ms) 뒤에 붙이고(칸이 밀려 들어오는 동안 썸네일 여러 장을 그려 버벅였음), `PosterBand` QR은 프로젝트마다 한 번만 만든다. **끌어다 놓기**: 목록 전체(`useFileDrop`, 개수가 다 찼어도 놓기는 받아 알림 — 안 받으면 브라우저가 그림을 열어 폼 내용이 날아감)와 폼 「홍보 포스터」 칸. 옛 주소 `/projects/[id]/poster`·`/poster/[posterId]`는 `?poster=`를 단 수정 화면으로 넘기는 페이지만 남았다.
  - 들어가는 길: 수정 폼 「홍보 포스터」 카드의 버튼, `/posters/start` → `/projects/<id>/edit?poster=list`. 상세의 빈 포스터 칸·걸린 포스터 크게 보기 창의 "포스터 바꾸기" → 상세에서 바로 연다(아래). 상세 머리의 "홍보 포스터" 버튼은 2026-11-07 중복이라 뺐다.
  - **상세에서도 같은 칸**(2026-11-08 사용자 결정 — "나에게만 보이는 안내" 카드 `PosterNudge`는 삭제): 걸린 포스터가 없으면 옆칸 맨 위에 점선 **빈 포스터 칸** `PosterSlot`(주인·팀원만, 공개만 — `ProjectDetail.posterSlot` = `posterSlotVisible`; 관리자 계정은 남의 프로젝트마다 뜨면 거슬려서 뺐다, × 없음). 누르면 수정 화면과 같은 `PosterSheet`가 상세 위에서 열린다(`ProjectDetailView posterSheet` — 서버 상세 페이지만 켬, 조건 `canEdit`·공개). 상세용은 `inForm={false}`: 목록을 미리 받지 않고 칸을 열 때 받으며(상세는 자주 열리니 서버 액션을 아낌), "저장하기와 따로" 안내를 뺀다. 닫을 때 바꾼 게 있으면 `router.refresh()`로 걸린 포스터가 옆칸에 바로 보인다(AI 포스터는 PNG를 뒤에서 찍는 몇 초 동안 빈 칸이 그대로일 수 있음). **빠른 상세**(목록에서 누른 겹침 화면)는 주소를 pushState로 바꾼 상태라 칸을 두지 않고, 빈 칸·"포스터 바꾸기"가 `/projects/<id>?poster=list` 서버 상세로 넘긴다(열린 채로 도착).
  - 칸 목록 화면: 맨 위 **포스터 띠 받기**(`PosterBandDownload`, 수정할 수 있는 사람 누구나 — `getBandAccess`/`decideBandAccess`, 관리자 제한 없음), 그 아래 **상세 페이지에 걸 포스터**(올리기·AI 새로 만들기·카드마다 걸기/내리기/지우기 — AI 만들기는 `access.canUseAi`). 버튼들은 `router.refresh()` 대신 칸이 준 `onChanged`·`onUploaded`·`onDeleted`로 목록을 다시 읽고, `createPoster`는 이동하지 않고 `{ id }`를 돌려줘 칸이 스튜디오를 연다.
- 띠 PNG는 **브라우저 캔버스**로 그린다(`band-canvas.ts`, 2480×472, 서버·Browser Rendering 안 씀). 모양은 `dshs-band.css` 좌표를 그대로 옮김, 글꼴은 사이트의 `IBM Plex Sans KR Subset`·`Geist Mono`, 긴 이름은 `bandHint` 16자에서 자름. 띠 CSS를 바꾸면 캔버스 좌표도 같이.
- 직접 API 키 붙여넣기는 안 함(부족한 건 그림 할당량이라 Gemini 키로는 안 늘고, 학생 장벽·키 보관 부담).

## 구조 — 섞기(사용자 결정 2026-11-06)
- **글·배치 = Gemini**(`POSTER_TEXT_MODELS`, `generateContent` 한 번에 받기 — 스트림 조각 파싱은 CPU를 씀). 응답 = ```json 그림 주문(선택) + ```html. HTML의 큰 그림은 `<img src="ART">` 자리 하나.
- **그림 = Workers AI `flux-2-klein-9b`**(`AI` 바인딩, `src/lib/posters/art.ts`). 주문 비율 그대로, 넓이만 `POSTER_ART_MAX_AREA`까지 줄여 요청(`fitArtSize`). base64는 디코딩하지 않고 data URI로 Cloudinary `dshs/posters`에 올려 URL만 저장.
- **보내는 정보**(Gemini): 이름·종류·플랫폼·소개 요약(한 줄 소개+상세 설명 1200자)·학생 부탁, 고칠 땐 현재 HTML+최근 부탁 4개. **처음 만들 때 소스코드 공개 + GitHub 저장소면** 저장소 설명·토픽(8개)·주 언어 + README(마크다운 정리 3000자, 있으면 상세 설명 요약 대신)를 더한다(`repo-fetch.ts`·`repo-context.ts`, 사용자 요청 2026-11-06). 사이트 주소·이메일·실명·팀원은 안 보냄. Workers AI에는 Gemini가 쓴 영어 그림 프롬프트+크기만.
- **그림 = 학교 Mac mini 먼저**(2026-11-06, 설계 `docs/superpowers/specs/2026-11-06-poster-mac-art-design.md`, 계획 `docs/superpowers/plans/2026-11-06-poster-mac-art.md`). 학교망을 열지 않으려고 **Mac이 일감을 당겨 간다**: 사이트는 `poster_art_jobs`에 넣고(`enqueueArtJob`, `src/lib/posters/art-jobs.ts`) 포스터 `art_job_id`를 기록한 뒤 바로 돌려준다. Mac은 anon 키 + 자기 토큰으로 RPC `claim_poster_art_job`(3초마다, lease 180초)·`poster_art_ping`(그리는 동안 15초마다)을 Supabase에 직접 부른다(Workers 요청 수를 안 씀). 다 그리면 `POST /api/poster-art/jobs/<id>/result`(Bearer Mac 토큰 + `X-Job-Secret`, 이미지 바이트 4MB까지, 매직 넘버 검사, Cloudinary엔 Blob 그대로 — base64 안 함)·실패는 `…/fail`. 응답 200(이미 done이어도)·404(인증·상태 틀림, 이유 안 알림)·413·415·502(Cloudinary 실패, Mac이 5·15초 뒤 재시도). 이 두 경로는 쿠키 없는 기계 전용이라 `isSameOrigin` 예외.
  - Mac 살아 있음 = 최근 30초 안 연락(`macsOnline`). 아니면 처음부터 Workers AI. 처음 만들 땐 `art_local`부터 잡고 없으면 `art`.

## 권한·제한
- **2단계 = 학생에게 열림**(2026-11-07): `POSTER_OPEN_TO_ALL = true`(`config.ts`) — 수정할 수 있는 사람(소유자·팀원·관리자) 누구나, 공개 프로젝트만(비공개로 바뀌면 숨김, 지우지 않음), 차단된 사람 불가. 판정 `decidePosterAccess`. 처리방침(Google Gemini 위탁·학습 가능, 포스터 그림)을 **같은 배포**에 넣어 전원 재동의(`.claude/rules/privacy.md`). 탭 닫힘 문제는 같은 날 다른 작업에서 Cloudflare Queues로 옮겨 해결됐다(아래 「긴 응답·내보내기」).

## 긴 응답·내보내기
- **만들기·고치기·다시 그리기 = Cloudflare Queues 일감**(2026-11-07, 탭을 닫아도 끝까지 저장). 예전엔 `heartbeatJson`으로 응답을 붙잡고 `ctx.waitUntil`에 맡겼는데, Cloudflare는 연결이 끊긴 뒤 waitUntil을 **30초까지만** 이어 가서 Gemini(1회 12~90초, 붐비면 503 → 다음 모델)가 남아 있으면 결과도 횟수도 사라졌다.
  - 흐름: `ask`·`redraw`(Workers AI 길만 — 학교 Mac 길은 원래 바로 돌려줌)가 권한·횟수를 확인하고 `enqueuePosterJob`(`ai-jobs.ts`) → `poster_ai_jobs`에 일감(부탁·스타일·캡처 + 요청 때 확인한 프로젝트 정보 `PosterActor` — 소비자에겐 로그인 쿠키가 없다) + 포스터 `ai_job_id`(조건부, 이미 있으면 409 `aiBusy`) + 큐 `poster-jobs`에 `{ jobId }` → 바로 `{ ok, queued, jobId }`.
  - 큐 소비자 = `custom-worker.ts`의 `queue()`(wrangler `main`이 이 파일 — OpenNext `.open-next/worker.js`의 fetch를 그대로 감쌈). 같은 Worker를 `WORKER_SELF_REFERENCE` service binding으로 `POST /api/poster-jobs/run`(헤더 `x-poster-job-sig` = 일감 id의 HMAC-SHA256, 키 = `SUPABASE_SERVICE_ROLE_KEY` — 새 비밀값 없음, `ai-jobs-logic.ts`)을 부르고 **응답을 끝까지 기다린다**(소비자 한 번 최대 15분). 실제 일은 Next 경로가 그대로 해서(`run-ai.ts` `runPosterAsk`·`runPosterRedraw`) CPU 10ms도 요청마다 따로. 404(서명 틀림)는 버리고, 5xx·연결 오류는 10초 뒤 두 번까지 다시 — `runPosterJob`이 queued → working을 조건부로 바꾼 요청만 돌리므로 중복 배달에도 한 번.
  - 횟수는 `UsageLedger`(`usage.ts`)로만 잡고 돌려준다: 잡은 것은 `poster_ai_jobs.holds`에 적고, 쓴 것(그림을 그렸거나 학교 Mac 일감이 맡음)은 `spend`로 뺀다. 끝나면 holds를 비운다. 일감이 중간에 죽으면 `settlePosterJob`이 막힘 판정(`judgeAiJobStuck` — queued 10분, working 시작 16분)으로 expired + `usage_released_at`을 조건부로 채운 요청만 남은 holds를 한 번 돌려준다. 적기 → 돌려주기 순서라 그 사이에 죽으면 덜 돌려줄 뿐 두 번은 아니다.
  - 브라우저: `{ queued }`면 `poster.aiJobId`를 두고 3초마다 `GET /api/posters/<id>/job?id=<jobId>`(정리도 여기서) → done(notice 알림)·failed(error 알림) 때 포스터를 바꾼다. 서버 페이지도 열 때 `settlePosterJob`, 아직 돌고 있으면 `aiJobId`로 이어서 기다린다(창을 닫았다 다시 열어도 "만드는 중"·결과가 보임). 돌고 있는 동안 되돌리기·다시 그리기·내보내기·보내기 꺼짐(되돌리기는 서버 액션도 거절 — 끝나며 저장하면 덮어씀). 실패 결과는 그 탭이 기다리고 있을 때만 알림으로 보이고(대화 기록엔 안 남김), 횟수는 돌려준다.
  - **큐를 못 쓰면 예전 방식**: `next dev`(소비자 없음)·바인딩 없음·일감/큐 넣기 실패면 `heartbeatJson`(15초마다 공백, 끝에 JSON, 브라우저 `parseHeartbeatBody`) + `keepAliveAfterDisconnect`로 직접 한다. 이때만 나가려 하면 묻는다(`useUnsavedWarning`, `POSTER_COPY.leaveWhileBusy`). 그래서 로컬 `npm run dev`로는 큐 길을 시험할 수 없다 — 운영(또는 `npm run preview`)에서 확인.
  - **대곽나루 서버**(`DSHS_RUNTIME=node`, 2026-11-11 시험 중 — `docs/25-naru-server.md`): 큐 대신 `enqueuePosterJob`이 같은 일감을 프로세스 안에서 돌리고(`node-jobs.ts` `runInBackground`), `keepAliveAfterDisconnect`도 같은 목록에 올린다. 그림은 `AI` 바인딩 대신 Workers AI REST(`art-rest.ts`, `CLOUDFLARE_AI_API_TOKEN`).
  - 큐 `poster-jobs`는 2026-11-07 `npx wrangler queues create poster-jobs`로 만들었다(계정 370e521d…, 무료 — 하루 10,000 operations, 메시지 하나 ≈ 3, 보존 24시간). wrangler.jsonc `queues`의 큐가 없으면 배포가 실패하니 지우지 말 것. 확인: `npx wrangler queues list`, 실패는 `wrangler tail`의 `[poster] 큐 …`.
  - 배포 순서: migration `20261107130000_poster_ai_jobs.sql`을 **먼저 따로 main 푸시**(Supabase 자동 적용) → 그다음 코드 푸시(Workers Builds). 코드가 먼저 가면 `ai_job_id` 칸이 없어 포스터 API가 깨진다.
- 학교 Mac 그림은 탭과 상관없이 끝나고, 탭을 닫은 사이 막혔으면 다시 열 때 서버 페이지가 정리하고 `artGaveUp`으로 브라우저가 한 번 클라우드로 다시 그린다(그 다시 그리기도 큐 일감).
- PNG·PDF = Cloudflare Browser Rendering REST(`/browser-rendering/screenshot`·`/pdf`, 무료 요금제 됨, 연속 요청 429). `waitForTimeout: 2000` — Google Fonts `display=swap`이라 없으면 대체 글꼴로 찍힌다. 토큰 `CLOUDFLARE_BROWSER_API_TOKEN`(Browser Rendering · Edit만).
